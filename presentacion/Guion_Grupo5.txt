PREPARACIÓN PARA PREGUNTAS (FUERA DEL TEXTO HABLADO)

Diapositiva 8: índices y rastreo
HASH sirve solo para igualdad (codigo = ?), que es lo que hace el rastreo; no sirve para rangos ni ORDER BY. Si hiciera falta buscar por prefijo se cambiaría a B-tree. idx_paquete_estado acelera los filtros por estado. El índice compuesto (paquete_id, fecha, id) deja los eventos ya ordenados. El índice único parcial uq_ruta_paquete_pendiente solo cubre filas con resultado Pendiente, así se conserva el historial pero hay una sola asignación activa. Revisar database/01-dbCreate.sql, EventoSeguimientoRepository.rastreoPaquete() y PaqueteService.rastrear().

Diapositiva 9: vista materializada
La vista guarda el resultado calculado; no se actualiza sola al insertar entregas. REFRESH CONCURRENTLY exige un índice único (idx_mv_rendimiento_centro_repartidor) y una vista ya poblada; permite leer durante el refresco. El porcentaje es entregas a tiempo sobre entregas exitosas (NULLIF evita dividir por cero). Los centros se recalculan sumando conteos, no promediando porcentajes. El cron del Spring es 0 0 3 * * * en zona America/Santiago y se puede cambiar con REFRESH_CRON; el pg_cron del script está solo como comentario. Revisar database/02-materialViews.sql y ReporteService.

Diapositiva 10: reporte de alertas
GET /api/reportes/alertas?umbral=85 solo lo puede llamar el despachador. Compara 100 * entregas_a_tiempo / entregas_totales con el umbral. El 80 % de la captura (8 de 10 en CD Santiago G5) salió de la base local de demostración; si se refresca la vista tras nuevas entregas puede cambiar. Revisar ReporteRepository y ReporteController.

Diapositiva 11: procedimiento asignar_ruta
FOR UPDATE por id ordenado evita interbloqueos entre asignaciones concurrentes. El INOUT p_ruta_id devuelve la ruta creada. ERRCODE 23514 es violación de restricción CHECK y P0002 es "no encontrado". La capacidad la valida el trigger por cada fila de ruta_paquete, no el procedimiento. Revisar database/03-storedProced.sql, asignar_ruta().

Diapositiva 12: trigger de capacidad
BEFORE INSERT actúa antes de guardar cada fila de ruta_paquete. NEW es esa fila. total_weight y total_volume incluyen la carga existente y el paquete nuevo. OR rechaza si cualquiera supera su límite. > permite igualdad. Los símbolos % son sustituciones del mensaje. 23514 es el código SQLSTATE de restricción. RAISE EXCEPTION interrumpe la operación; RETURN NEW permite continuar si no hubo error. Antes del fragmento, FOR UPDATE OF r,v bloquea ruta y vehículo y COALESCE convierte una suma vacía en cero. Revisar database/04-triggers.sql, check_route_capacity().

Diapositiva 13: procedimiento de fallos
:= asigna el contador incrementado. Con intentos inicialmente en cero, > 3 se cumple al cuarto fallo. El contador es de fallos, no de éxitos. Se registra el resultado y un evento, se reprograma un día o se crea el retorno hacia el centro de origen con fecha compromiso a tres días. No se modifica el compromiso original. Revisar database/03-storedProced.sql, registrar_entrega_fallida().

Diapositiva 14: auditoría de destino
El trigger es BEFORE UPDATE OF direccion_destino. Solo audita si OLD.despachado_at no es nulo y la dirección cambió; el usuario viene de la variable de sesión app.user_id que fija el servicio. En Entregado o Devuelto a origen el cambio se rechaza. El trigger auditoria_inmutable (BEFORE UPDATE OR DELETE) rechaza cualquier modificación de la tabla de auditoría. Revisar database/04-triggers.sql.

Diapositiva 15: seguridad y acceso al rastreo
SecurityConfig valida firma con el JWKS de Keycloak, emisor y audiencia; si el sub no tiene perfil local o el rol del token no coincide con el del perfil, rechaza con 401. ! significa negación. p.getPaqueteId() identifica el paquete. u.rol() y u.uid() describen al usuario autenticado. Si esVisible devuelve false, se lanza AccessDeniedException. El código de seguimiento no reemplaza los permisos. Revisar backend/src/main/java/com/example/demo/config/SecurityConfig.java y services/PaqueteService.java, rastrear().

Diapositiva 16: registro de usuario
El endpoint es público (permitAll solo para POST /api/auth/registro). RegistroService normaliza el correo, rechaza duplicados (409), crea el usuario en Keycloak con la cuenta de servicio logistica-admin (roles manage-users y view-realm) y asigna el rol cliente fijo. Si el INSERT falla, KeycloakAdminClient.eliminarUsuario compensa. Revisar RegistroService, KeycloakAdminClient y AuthController.

Diapositiva 17: cuentas del personal
Por qué el personal no se registra solo: el rol define los permisos; si el formulario público pudiera elegirlo, cualquiera se daría el rol despachador (escalada de privilegios). /registro fija el rol cliente en el servidor (RegistroService); crear repartidores y despachadores exige ser despachador (UsuarioController, hasRole DESPACHADOR). Contraseña temporal: KeycloakAdminClient la envía con temporary = true, así Keycloak exige cambiarla en el primer inicio de sesión. Compensación: si el INSERT en usuario falla, UsuarioService llama a keycloak.eliminarUsuario, igual que en el registro. Se envía contraseña (mínimo 8) o keycloakId, no ambos: vincular una cuenta existente por keycloakId no toca Keycloak. PUT sincroniza nombre, correo y rol con Keycloak; DELETE elimina también la cuenta. Un despachador no puede borrarse ni cambiarse el rol (409). El realm tiene editUsernameAllowed para sincronizar el correo, que es el nombre de usuario. Revisar UsuarioService, KeycloakAdminClient y UsuarioController.

Diapositiva 18: paginación
Consulta.listar arma el COUNT sobre el mismo WHERE que el SELECT, usa parámetros enlazados y un ORDER BY fijo por clave primaria (nunca desde la entrada del usuario). El tamaño por defecto es 20 y se limita a 1..100. Sin page se devuelve la lista completa. Pagina.responder() pone el total en X-Total-Count y SecurityConfig lo expone por CORS. Revisar repositories/Consulta.java y dto/Pagina.java.

Diapositiva 19: formulario y números
raw es la entrada. ?? reemplaza null o undefined por texto vacío. trim elimina espacios externos y replace convierte la coma decimal en punto. La expresión regular exige dígitos y una parte decimal opcional: rechaza letras, signos y notación exponencial. test devuelve booleano. El operador ternario elige Number(s) o NaN. Cero pasa el formato pero positiveDecimalError lo rechaza con n <= 0. validate devuelve los mensajes de campos inválidos. Object.keys(found).length cuenta esos campos; return sale antes del POST. La validación completa también limita dos decimales y tamaño. Revisar frontend/src/lib/numbers.js y frontend/src/pages/cliente/ClienteNuevo.jsx.
